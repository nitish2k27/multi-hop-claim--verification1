Anatomy of a Verification

One claim, followed from the keystroke in the browser to the rendered report — every file, every function, every line it passes through.

The claim under test India's software exports reached 222 billion dollars in 2024-25
TRUE @ 92% confidence outcome verified 35 candidates → 3 evidence 1 LLM call total 22.5s cold

Every number on this page came from a single run on 2026-08-17 against index v1 (1,687 documents, 13,101 chunks), start to finish in one process. Nothing is illustrative.

On the timings and the confidence

22.5 s is a cold run — roughly 10 s of it is loading four CPU models and unpickling 13,101 BM25 entries, paid once per process. The same claim through the warm HTTP API returns in 5.19 s. The API pays this cost at startup rather than during the first request (serve/api.py:345), so the first verification is as fast as the tenth.

Confidence moves a few points between runs — 78, 85, 92 across three — because generation runs at temperature 0.2. The verdict, the evidence set and the retrieval figures are stable; treat the confidence as a band, not a reading.

OverviewTwo processes, one stream

The browser holds a React app; the server holds a LangGraph state machine. They meet at exactly one place — a POST that never closes until the graph finishes, dribbling one server-sent event per completed node.

06

stanceLabel each document against the claim

4.9s · second local model · 413 MB

One batched forward pass over all (claim, evidence) pairs. The matched chunk is preferred over the full article: it is what the retriever actually scored, and it fits inside the model's 256-token training window.

serve/nodes/stance.py:106 stance_and_credibility(state)
└─ serve/nodes/stance.py:72 _classify(claim, texts)
└─ core/models.py:116 stance_detector() bert-base-cased, 208k FEVER pairs
└─ torch softmax → SUPPORTS / REFUTES / NOT ENOUGH INFO

Credibility is not computed here — the compressor pipeline already attached it during retrieval. This node only adds stance, then summarises both for the prompt.

[1] SUPPORTS economictimes.indiatimes.com
[2] NEUTRAL economictimes.indiatimes.com

On this claim the BERT and the LLM agreed item for item. They often do not — and when they disagree the prompt instructs the model to follow the evidence text, because this classifier is 73.6% accurate and weakest exactly where it matters most (REFUTES, F1 0.74). Its label reaches the prompt as a signal with a confidence attached, never as the verdict.

The model named here is not the one this was designed against

This trace was captured the day Groq retired llama-3.3-70b-versatile. It answered at 13:59 and returned 404 model_not_found at 14:17 — the same key, twenty minutes apart. core/llm.py:50 checks the configured models against GET /openai/v1/models at startup precisely so this surfaces as a clear boot error rather than a mid-request 404, and .env.example carries the warning that Groq deprecates on a rolling basis.

Nothing about the pipeline changed — only GROQ_MODEL. That is the payoff of putting the model behind get_llm() and constraining its output to a Pydantic schema: the swap was one line in .env.

The numbering in format_evidence() is a contract with three consumers: the prompt that renders it, the stance list that indexes into it, and the validator that checks the model's evidence_index against it. Change the numbering in one place and citation checking silently stops working.

Worth noticing

The model volunteered the missing publication date as a limitation — that date gap is a real, known property of the current corpus, and the credibility scorer had already flagged it independently (date_reliable: false, recency dropped from the weighting and the score recomputed on domain and source type alone).

Evidence items 2 and 3 cleared the relevance floor at 0.959 and 0.350 and were still marked directly_relevant: false. That is the division of labour the whole design rests on: the floor removes what is unrelated, and only a reader — here, the LLM — can remove what is related but beside the point. Item 2 is an article about India's export figures that never mentions software. A system with only a threshold would have counted it as corroboration.
